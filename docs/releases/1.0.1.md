# The Vault Render Optimization 1.0.1

Release date: 2026-11-27

VRO 1.0.1 brings full compatibility with The Vault 22.0.0 (`7209`), 3.22.0 (`7210`), and 22.0.1 (`7237`), fixes GPU animated-item texture updates, virtual-world barrel culling, and player mob pushback, and adds a set of default-on terrain, HUD, audio, and render hot-path FPS optimizations that help both default CPU rendering and Oculus shader packs.

- **Minecraft:** 1.18.2

## Detailed changes since v1.0.0 (`v1.0.0...v1.0.1`)

### Added (New FPS & hot-path optimizations)

1. **Angle-based chunk section visibility path occlusion (`section_distance_culling.angle_section_occlusion`, default `true`, hot-configurable):**
   - Masks geometrically impossible opposing-face BFS paths (`DOWN ↔ UP`, `NORTH ↔ SOUTH`, `WEST ↔ EAST`) out of Embeddium `0.3.18`/`0.3.19` `ChunkGraphInfo.visibilityData` during `RenderSectionManager.iterateChunks`.
   - Reduces rendered terrain section count and chunk-graph BFS work with zero visual difference, helping both default rendering and shader packs.
   - Automatically skips spectator mode, Compare Mode, and Oculus orthographic shadow passes (`OculusShadowState` reading `ShadowRenderer.ACTIVE`), and yields automatically when `flerovium` is installed.
   - Verified mathematically against Embeddium's `(from.ordinal() << 3) | to.ordinal()` bit layout with a 100,000-ray randomized Monte Carlo zero-false-cull test (`AngleSectionOcclusionTest`).
2. **Built-in ImmediatelyFast upgrades (from upstream `1.20` `e91270df`, LGPL-3.0-or-later; skipped when standalone `immediatelyfast` is installed):**
   - `MixinVertexBuffer` now leaves `GL_STATIC_DRAW` vertex buffers intact instead of forcing `GL_DYNAMIC_DRAW` + `glBufferSubData`, avoiding suboptimal driver buffer placement on static sky/star/cloud/world meshes.
   - Added `@Pseudo` `MixinItemBorders` targeting `com.anthonyhilyard.itemborders.ItemBorders.render` (also invoked by `ModdedItemBorders`) to batch multi-quad slot-border fills into one pass when no outer HUD fill batch is active.
3. **Sound engine distance and static-channel culling (`render_fast_paths.sound_distance_culling`, `render_fast_paths.sound_channel_culling`, default `true`, hot-configurable; adapted from Flerovium `512e0307`, LGPL-3.0-only):**
   - Skips non-streaming sounds when OpenAL's static channel pool is already saturated (`usedCount >= maxCount`) before full channel/future setup runs only to be rejected.
   - Skips non-relative, non-looping, non-tickable linearly attenuated sounds that are beyond audible range plus a 4-block safety margin of all active listener references (OpenAL listener, main camera, and `player.getEyePosition()` — preventing stale-listener muting on Elevator/teleport jumps) before `SoundEngine.play` allocates vectors or requests an OpenAL handle, while preserving subtitle listeners for audible sounds.
   - Yields automatically when `flerovium` is installed.
4. **Sky-angle caching (`render_fast_paths.sky_angle_caching`, default `true`, hot-configurable; informed by BadOptimizations `3.0.0`, ISC):**
   - `LevelRendererSkyAngleMixin` caches `ClientLevel.getTimeOfDay(partialTick)` across both calls inside a single `LevelRenderer.renderSky` frame.
   - Yields automatically when `badoptimizations` is installed.
5. **Internal hot-path cleanups:**
   - **Sophisticated Storage barrels (`LimitedBarrelRendererMixin`):** skips `renderFillLevels` when the barrel's front display is already culled (`!vro$frontDisplayVisible`).
   - **Create contraptions (`SectionedContraptionRenderer` / `CreateFlwContraptionMixin`):** skips `setup(shader)` for empty contraption render layers (`FlywheelData.hasLayer`).
   - **Flywheel shader bridge (`FlywheelShaderCompatState`):** replaces `synchronized` hot-path state checks (`isRenderPathActive`, `shouldUseShaderInstancing`, `hasPipeline`, `hasFailed`, `deferModelBuilds`) with lock-free `volatile` reads.

### Changed (Vault Hunters 22.0.x upstream-fix handoffs)

Every Vault compatibility gate inspects the live Vault classes rather than version strings, so older Vault builds retain every VRO optimization while newer Vault builds run Vault's own implementation cleanly:

- **Vault 22.0.0 (`7209`), 3.22.0 (`7210`), and 22.0.1 (`7237`):** VRO automatically leaves seven fixes to Vault when Vault ships them itself:
  1. Cached Vault event listener dispatch (biome colours, dimension effects, ambient light, level rendering)
  2. Learned client ability-list cache
  3. Tool model and gear lookups in the tool renderer
  4. Armour texture cache
  5. Single armour layer factory per model
  6. Skipping the item drawn inside spawners *(note: Vault 7209/7210 also culls survival spawners as block entities; that behavior comes from Vault, not VRO)*
  7. Keeping `ItemStack.EMPTY` free of entity references (`MixinItemStack.keepEmptyStacksFreeOfEntityLinks` in `7237`)
- **`/vro particles stress nova`:** now supports Vault 22.x's `ClassicAbilityParticles` and `NovaWaveParticles` alongside legacy `NovaParticleMessage`.

### Fixed

- **GPU items animated textures (`EmbeddiumSpriteTracking`, `GpuItems`, `GpuBlockModels`):** With GPU items enabled, animated item textures and animated block models drawn by block entities could stop animating under Embeddium/Rubidium's "Animate Only Visible Textures" because VRO rendered them without marking their sprites active. VRO now marks those sprites as drawn just like the normal renderer.
- **Sophisticated Storage virtual-world barrel culling (`BarrelFrontVisibility`):** Skips front-display culling when a barrel renders inside a virtual or contraption world (such as Create contraptions) rather than the active `ClientLevel`, preventing barrel displays from disappearing due to mismatched world-space camera coordinates.
- **Client entity collision player pushback (`ClientLivingEntityCollisionMixin`):** Excludes `LocalPlayer` from cancelling `pushEntities()` so the player retains vanilla mob pushback while non-player mobs continue skipping redundant client-side push scans.

All four new config options default to `true`, take effect immediately without a restart, appear in VRO's in-game settings screen, and yield in Compare Mode:

| --- | --- | --- | --- | --- |
| `section_distance_culling` | `angle_section_occlusion` | `true` | Yes | `flerovium` (also skips spectator & Oculus shadow pass) |
| `render_fast_paths` | `sound_distance_culling` | `true` | Yes | `flerovium` |
| `render_fast_paths` | `sound_channel_culling` | `true` | Yes | `flerovium` |

Built-in ImmediatelyFast upgrades (`MixinVertexBuffer` and `MixinItemBorders`) remain gated behind VRO's built-in ImmediatelyFast switch and step aside completely when standalone `immediatelyfast` is installed.

## Pre-release fixes included before release

Pre-release testing on VaultCrafters caught and resolved two issues before publication:

- **Elevator and teleport sounds:** `SoundEngineOptimizationMixin` initially checked distance only against `SoundEngine.listener.getListenerPosition()`, which updates once per rendered frame (`renderLevel`). On teleports (such as Elevator blocks jumping more than 16 blocks), `ClientboundSoundPacket` can run before the next frame updates the listener, muting the teleport sound. Distance culling now takes the minimum distance across the OpenAL listener, `GameRenderer.mainCamera`, and `Minecraft.player.getEyePosition()`, adds a 4-block safety margin, and skips all `TickableSoundInstance`s.
- **Zoom-mod compatibility (JustZoom):** A planned zero-effect FOV modifier shortcut (`AbstractClientPlayerFovMixin` / `skip_redundant_fov_calculation`) conflicted with JustZoom's smooth zoom when Minecraft's `FOV Effects` slider was set to `0%`, because cancelling `AbstractClientPlayer.getFieldOfViewModifier` at `HEAD` ran ahead of JustZoom's `HEAD` hook. That mixin and config option were removed before release so zoom and camera mods remain untouched.

## Upgrade

1. Stop Minecraft.
2. Remove or disable the older VRO jar in your instance's `mods` folder.
3. Place `vault_render_optimization.1.0.1.jar` into `mods` (keep only one active VRO jar).
4. Launch—no server installation, world migration, or config reset is needed.
