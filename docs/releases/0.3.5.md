# The Vault Render Optimization 0.3.5

Release date: August 16, 2026

VRO 0.3.5 allows shader packs to provide dedicated Flywheel scene and shadow
programs. Compatible packs can retain Flywheel GPU instancing while tailoring
their Create rendering directly to the pack instead of relying only on VRO's
generated shader transformation.

## Download

Install the runnable artifact:

```text
vault_render_optimization.0.3.5.jar
```

Stop Minecraft and keep only one active VRO JAR. No server installation, world
migration, cache deletion, or configuration reset is required.

## Dedicated Flywheel shader programs

- Shader packs can supply `gbuffers_flw` for Flywheel scene rendering and
  `shadow_flw` for Flywheel shadow rendering.
- VRO searches the active dimension first and then the shader-pack root,
  matching Oculus shader-program lookup behavior.
- Both modern and legacy dedicated-program layouts are supported.
- `/vro create status` reports `DEDICATED`, `GENERATED`, or `FALLBACK`
  independently for scene and shadow programs.
- Missing or invalid dedicated programs do not disable shaders. VRO retries its
  existing generated compatibility path and retains the standard Flywheel
  renderer if compilation still fails.
- Shader packs without dedicated programs keep the VRO 0.3.4 behavior.

VRO does not bundle or redistribute a shader pack. Dedicated programs remain
part of the selected shader pack and can preserve its own lighting, materials,
fog, reflections, transparency, and shadow behavior.

## Validation

- Built the final artifact against Minecraft 1.18.2 and Forge 40.3.11+.
- Confirmed dedicated scene and shadow discovery with public Oculus 1.6.4,
  Rubidium 0.5.6, Create 0.5.1.i, and Flywheel 0.6.11-107.
- Completed five dedicated-program runs and five generated-path control runs
  at 3840x2160 fullscreen with shaders enabled, 32-chunk render distance, and
  five loaded contraptions totaling 6,022 rendered blocks.
- All ten routes completed with deterministic benchmark guards passing and no
  shader compilation or runtime OpenGL failure during either measured set.
- In that specific scene, the dedicated path measured 177.69 average FPS
  versus 138.95 for the control. This result validates the implementation and
  is not a universal performance guarantee.

## Compatibility

| Component | Supported baseline |
| --- | --- |
| Minecraft | `1.18.2` |
| Forge | `40.3.11+` in the Forge 40.x line |
| Environment | Client only |
| Create | `0.5.1.i` |
| Flywheel | `0.6.11-107` |
| Oculus | Public `1.6.x`, verified with `1.6.4` |
| Renderer | Rubidium `0.5.6` or supported Embeddium releases |
| Vault Hunters | Official, Remastered, Wolds, and selected custom baselines |

See [Create shader instancing compatibility](https://github.com/HoYin1600p/The-Vault-Render-Optimization/blob/v0.3.5/docs/FLYWHEEL_SHADER_COMPAT.md)
for shader-pack integration details, diagnostics, configuration, and recovery.
