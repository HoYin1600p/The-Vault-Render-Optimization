# The Vault Render Optimization 0.4.1

VRO 0.4.1 is a major client-rendering update for Minecraft 1.18.2. It adds
lower-cost visible particles, selected later ModernFix render/model
optimizations, guarded Embeddium/Rubidium corrections, and new chunk-update
paths aimed at smoother frame delivery in busy bases and while travelling.

This remains a client-only update. It does not change loot, server rules,
world data, visible particle counts, or server gameplay.

## Chunk rendering and frame pacing

- VRO now enables each supported renderer's native asynchronous chunk-update
  path by default, without rewriting that renderer's own setting. This reduces
  render-thread stalls while preserving its normal task lifecycle.
- Validated Embeddium 0.3.18/0.3.19 builds can update translucent terrain by
  replacing only changed index data instead of copying and re-uploading
  unchanged vertices.
- An independently switchable adaptive budget measures completed build and
  upload costs, applies bounded queue pressure, and protects aged updates.
  Initial terrain, cached-terrain loading, backlogs, and waiting work fall back
  to the renderer's native path so distant cached chunks are not artificially
  throttled.
- `/vro chunks status`, `/vro chunks defer`, `/vro chunks sorting`, and
  `/vro chunks budget` expose hot controls and bounded diagnostics.

Visible block changes can arrive slightly later while native deferral is
active. Compare Mode and the explicit off controls restore native preferences
immediately.

## Visible-particle efficiency

- Ordinary particle billboards derive their corners from the camera basis
  without four repeated quaternion rotations.
- Supported Rubidium and Embeddium stacks receive the same geometry through
  their packed particle writer; vanilla rendering retains its normal writer.
- Particles in the same block can share one bounded same-tick light result.
- Empty particle queues skip renderer setup without hiding or shortening any
  visible effect.
- Custom particle renderers and custom light overrides retain their own paths.
- VRO yields automatically to Flerovium and can hot-yield billboard ownership
  to Rubidium or Embeddium.

Use `/vro particles` to inspect or hot-change billboard ownership, shared
lighting, and diagnostics. These controls do not require a client restart.

## ModernFix render and model backports

Eleven later ModernFix features are adapted to Forge 1.18.2:

- allocation-light chunk meshing with vanilla traversal order;
- duplicate `BufferBuilder` allocation prevention;
- reload-safe entity-model cube compaction;
- a bounded profile-texture URL/hash cache;
- multipart selector predicate caching;
- lower-allocation model-variant traversal;
- immutable transformation hash caching;
- concurrent Forge OBJ caches;
- guarded STB texture-atlas stitching for sufficiently large atlases;
- corrected Forge model-data concurrency; and
- synchronized nullable CTM metadata caching for the validated CTM layout.

Each feature has an independent restart-bound option. VRO yields when the
matching ModernFix option is genuinely active and preserves the established
Fluidlogged, Isometric Renders, Cracker's Wither Storm Mod, Rubidium,
Embeddium, and CTM compatibility gates. `/vro backports` reports the owner and
reason chosen at startup.

## Embeddium and Rubidium renderer corrections

Eight corrections transferred from the supported Embeddium fork now have
VRO-owned implementations:

- custom block face hiding receives the true adjacent block position;
- optimized vertex sinks fall back safely when no backing buffer exists;
- CodeChickenLib custom renderer lookup avoids repeated registry scans when
  the validated optional integration is present;
- useful native vertex buffers are retained with a deterministic peak bound;
- asynchronous buffer arenas grow preemptively using fixed, capped headroom;
- non-luminous fluids retain reload-safe smooth-lighting selection;
- shader color returns to white after each chunk layer; and
- equivalent chunk rebuild requests are coalesced without dropping stronger
  updates or scheduling a second non-sort build over an active rebuild.

Unknown or ambiguous renderer combinations fail closed. The original private
fork copies were removed only after automated, in-game, and single-owner
validation completed.

## Shader and startup fixes

- The Vault's native grayscale shader is now bound while its startup values
  are uploaded, eliminating the two related `No active program` OpenGL errors.
- Flywheel block-model readers now follow the buffer's actual vertex format
  through Oculus pipeline changes and the Distant Horizons-ready startup
  reload. Instanced model work waits safely while an extended format is active
  without a shader pipeline.
- Both native copies owned by the extended Flywheel reader are released when
  the reader is discarded.

## Compatibility and defaults

- VRO remains client-only on Minecraft `1.18.2`, Forge `40.3.11+` in the
  Forge 40.x line, and Java 17.
- ModernFix and renderer-transfer options are resolved at startup and require
  a restart after their config values change.
- Particle and chunk-update controls are hot and take effect immediately.
- Compare Mode yields performance-sensitive paths while retaining narrow
  correctness guards.
- Vault Hunters remains optional. Generic render, model, particle, and
  renderer-stack improvements still load without it.

## Verification

- Complete unit suite and clean production build.
- Five-pack compile compatibility matrix covering VaultCrafters Bootstrap,
  Asgard-SMP, Wolds Vaults 0.32.2 and 0.33.0, and Vault Hunters Third Edition.
- Stock Embeddium and Rubidium layout verification.
- Live renderer pressure covering rapid block changes, fluids, block entities,
  mass mob removal, resource/shader reloads, dimensions, Create/Flywheel,
  Botania, custom blocks, Cake rooms, and Distant Horizons initialization.
- Post-transfer single-owner control after the private fork implementations
  were removed.
- VaultCrafters validation of the revised cached-terrain loading guard and
  adaptive chunk-pacing controls.

## Download and upgrade

Install `vault_render_optimization.0.4.1.jar`. Stop Minecraft, replace the old
VRO JAR, and keep only one VRO version in the `mods` folder. No server
installation, world migration, cache deletion, or configuration reset is
required.
