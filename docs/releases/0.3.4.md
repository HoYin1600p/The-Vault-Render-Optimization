# The Vault Render Optimization 0.3.4

Release date: August 16, 2026

VRO 0.3.4 adds substantial Create rendering improvements, restores Flywheel
GPU instancing while supported public Oculus shaders are active, and includes
several long-session stability fixes accumulated since 0.3.3.

## Download

Install the runnable artifact:

```text
vault_render_optimization.0.3.4.jar
```

Stop Minecraft and keep only one active VRO JAR. No server installation, world
migration, cache deletion, or configuration reset is required.

## Create contraption rendering

- Large contraptions containing at least 512 rendered blocks are divided into
  cached 16-block render sections. Off-screen sections can be culled without
  simplifying models, textures, lighting, or animation.
- Special block entities and movement actors inside contraptions receive
  conservative frustum checks.
- Empty special-renderer buffer flushes are skipped.
- Belts, arms, deployers, portable storage interfaces, and mechanical rollers
  use tighter directional render bounds where supported.
- Compare Mode rebuilds Create world renderers so enabled and disabled tests do
  not reuse meshes produced under the other condition.

## Flywheel shaders

- Added compatibility for Flywheel GPU instancing with the public Oculus 1.6.x
  shader pipeline, Create 0.5.1.i, and Flywheel 0.6.11.
- Verified the compatibility path with both Rubidium 0.5.6 and supported
  Embeddium stacks.
- VRO restores Flywheel's upstream-default `INSTANCING` backend when a modpack
  ships with the backend set to `OFF`.
- Unsupported hardware, unsupported mod versions, or shader compilation
  failures retain Flywheel's standard safe renderer instead of forcing the
  compatibility path.
- Automatic instancing can be disabled with
  `create_rendering.auto_enable_flywheel_instancing=false`.

The following client-side commands apply immediately:

```text
/vro create status
/vro create shader_compat status
/vro create shader_compat on
/vro create shader_compat off
```

See [Create shader instancing compatibility](https://github.com/HoYin1600p/The-Vault-Render-Optimization/blob/v0.3.4/docs/FLYWHEEL_SHADER_COMPAT.md)
for the complete support boundary and recovery behavior.

## Performance and lifecycle improvements

- Vault Loot Beams tooltip data is created only when an item is evaluated for
  rendering and is cleared when the client world unloads.
- iSpawner display-item selection no longer creates a stream and temporary list
  every frame; ordinary displays may also use normal frustum culling.
- Minecraft's global empty item stack no longer retains the last synchronized
  dropped-item entity.

## Stability fixes

- Delayed obsolete Powah cable unloads can no longer remove a newer cable at
  the same position and interrupt the surrounding chunk update.
- Xaero's World Map cache validation and writes now share the region lock.
  Invalidated queued writes are cleaned up instead of crashing the client.

## Validation

- Built the final artifact against the supported Minecraft 1.18.2 and Forge
  40.3.11+ toolchain.
- Confirmed launch and rendering behavior with public Rubidium and stock
  Embeddium configurations.
- Tested five shader disable/enable cycles, three shader reloads, an
  Overworld-Nether-Overworld round trip, compatibility fallback and recovery,
  and a forced Flywheel `OFF` restart.
- The Rubidium acceptance run used a true 3840x2160 fullscreen framebuffer and
  five loaded contraptions totaling 6,022 rendered blocks. No stale, frozen, or
  corrupted frame was observed.
- The final 2,400-frame Rubidium sample measured 136.15 average FPS, 7.272 ms
  median, 8.057 ms p95, and 8.570 ms p99. These figures validate this specific
  test scene and are not a universal performance guarantee.

## Compatibility

| Component | Supported baseline |
| --- | --- |
| Minecraft | `1.18.2` |
| Forge | `40.3.11+` in the Forge 40.x line |
| Environment | Client only |
| Create | `0.5.1.i` |
| Flywheel | `0.6.11-107` |
| Oculus | Public `1.6.x`, verified with `1.6.4` |
| Renderer | Rubidium `0.5.6` or supported Embeddium releases |
| Vault Hunters | Official, Remastered, Wolds, and selected custom baselines |

Optional integrations remain dormant when their target mod is absent. VRO is
not required on the remote server.
