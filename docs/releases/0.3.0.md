# The Vault Render Optimization 0.3.0 - Initial Public Release

Release date: August 2, 2026

VRO 0.3.0 is the first public release of the client-side Vault Hunters runtime
optimization and stability project. It reduces repeated gear, HUD, event,
collision, particle, and renderer work; cleans up selected world-attached
state; and keeps correctness fixes available even when performance paths are
disabled for comparison.

## Download

Install the runnable artifact:

```text
vault_render_optimization.0.3.0.jar
```

Do not install a sources jar as a mod. Keep only one active VRO jar.

## Highlights

- Better frame-time consistency in four controlled Vault Hunters clients.
- Lower repeated Vault gear, HUD, tool-model, ability, damage-number, and
  render-event work.
- Less duplicate client collision work around dense mob processing.
- Conservative particle, empty-render, tutorial, debug, and renderer-lookup
  fast paths.
- Cleanup of stale Create Addition and Powah world references.
- Recovery from two deterministic client-only stale-state crashes.
- Correct Vault and Xaero world-map key ownership.
- Immediate, persistent Compare Mode for paired benchmarks.

## Vault rendering improvements

- Vault armor durability is reused while the gear's serialized data remains
  unchanged, with a one-second safety refresh.
- Armor state uses Vault's own gear cache, while armor texture and model
  selections are retained for repeated frames.
- Identified Vault tool models are cached; unidentified animated previews keep
  their established behavior.
- The learned ability list is retained until the client receives an ability
  update.
- Floored damage numbers reuse Vault's existing formatter rather than creating
  a formatter for each number every frame.
- Selected high-frequency Vault render events reuse an ordered listener
  snapshot and invalidate it whenever listener registration changes.

## General client improvements

- Client-only wall checks and living-entity pushes are skipped because the
  server remains authoritative for movement and collision results.
- Particle block-light results are reused only within the same client tick and
  block position.
- Particle, toast, tutorial, and supported debug setup is skipped only when
  there is no work to perform.
- Non-player entity and block-entity renderer lookups are cached and rebuilt
  after resource reloads.

VRO does not lower animation rates, reduce particle counts, perform
asynchronous rendering, or cache shader-sensitive sky or lightmap state.

## Stability and compatibility fixes

- Create Addition energy networks and Powah cable networks release entries for
  an exact world when it unloads.
- Vault Integrations altar conduits repair a missing client placement position
  before continuing their tick.
- Powah replaces an obsolete client cable entry and continues normal network
  refresh instead of terminating after replacement.
- The Vault's `M` binding consumes input only while the client is in a Vault,
  preserving Xaero's World Map in other dimensions.

Crash guards, cleanup, and key compatibility remain active in Compare Mode
because they are correctness behavior rather than performance claims.

## Performance

A deterministic campaign completed 40 accepted trials: five VRO-enabled and
five disabled runs in each of four clients.

Unweighted mean improvements across those clients were:

- average FPS: 5.35%;
- 1% low FPS: 30.66%;
- 0.1% low FPS: 35.07%;
- p99 frame time: 13.94%;
- average client CPU time: 4.49%.

Frames over 16.7 ms decreased in all four clients. Pack-level average-FPS
results varied, so the supported conclusion is improved frame consistency,
not a guaranteed fixed FPS increase.

See [Performance validation](../PERFORMANCE_VALIDATION.md) for the complete
controls, table, and interpretation.

## Configuration and commands

VRO creates:

```text
config/vault_render_optimization-client.toml
```

Generic render fast paths are individually configurable and enabled by
default.

| Command | Result |
| --- | --- |
| `/vro` | Reports Compare Mode |
| `/vro compare on` | Saves and immediately disables performance paths |
| `/vro compare off` | Saves and immediately enables configured paths |
| `/vro compare status` | Reports Compare Mode |

See [Configuration and commands](../CONFIGURATION.md) for every key and default.

## Optional-mod ownership

- VRO yields client collision mixins to Entity Collision FPS Fix.
- VRO yields equivalent empty-work and renderer caches to BadOptimizations.
- VRO yields particle-light caching to Particle Core or Flerovium.

These ownership choices are made during startup, preventing duplicate
transformations while allowing users to migrate without removing every
standalone mod first.

## Upgrade and removal

1. Stop Minecraft.
2. Remove or disable the previous VRO jar.
3. Place `vault_render_optimization.0.3.0.jar` in `mods`.
4. Confirm that only one VRO jar is active.

No world migration, cache deletion, or server change is required. Removing VRO
does not alter saved worlds.

## Known limitations

- Performance gains depend on the scene, pack, hardware, and which standalone
  optimization mods already own overlapping work.
- Compare Mode is a runtime performance control; adding or removing an overlap
  mod still requires a restart.
- The four-client campaign measured shaders and Distant Horizons disabled.
  Those stacks remain compatibility targets rather than part of the published
  percentage claim.
- Dedicated-server installation is unnecessary and not a supported release
  target.
