# The Vault Render Optimization 0.4.0

Release date: August 28, 2026

VRO 0.4.0 adds a complete client-only update-notification system. It checks a
VRO-owned GitHub manifest in the background, coordinates its main-menu row
with other HoYin1600p mods, and can show a bounded-cadence in-world reminder
whose download link is fixed to VRO's official CurseForge page.

The release does not add automatic downloads, forced upgrades, analytics, or
server-side behavior. Network, manifest, or local-state failures remain
nonfatal and hide the notice.

## Download

Install the runnable artifact:

```text
vault_render_optimization.0.4.0.jar
```

Stop Minecraft and keep only one active VRO JAR. No server installation, world
migration, cache deletion, or configuration reset is required.

## Update manifest and network behavior

- VRO fetches
  `https://raw.githubusercontent.com/HoYin1600p/The-Vault-Render-Optimization/main/update.json`
  asynchronously so startup and rendering do not wait for the network.
- Connections are limited to five seconds, requests to ten seconds, and
  responses to 262,144 characters.
- Non-successful HTTP responses, timeouts, abrupt connection closure,
  malformed JSON, missing Minecraft promotions, and oversized responses fail
  closed.
- The installed version comes from Forge's active VRO mod container rather
  than a second hard-coded version.
- Manifest messages accept optional `[CRITICAL]` and `[NORMAL]` prefixes,
  normalize whitespace, remove the prefix before display, and cap displayed
  text at 96 characters.
- The clickable target is always
  `https://www.curseforge.com/minecraft/mc-mods/vault-render-optimization`.
  Remote JSON cannot replace the download destination.

## Main-menu and chat notices

- Every participating HoYin1600p mod receives a deterministic main-menu row.
  Rows are sorted by short display name and mod ID so they do not overlap.
- Critical updates render in red; normal updates render in gold.
- In-world reminders add a clickable, underlined CurseForge link with hover
  text.
- Critical reminders become due on every fifth eligible launch. Normal
  reminders become due on every tenth eligible launch.
- A JVM becomes eligible only after a successful update result and the first
  playable world frame.
- Each JVM advances the reminder counter at most once and displays at most one
  chat reminder. Rejoins, disconnects, dimension changes, and transfer-style
  receiving screens cannot advance or repeat the reminder.
- Reminder state is written ten client ticks after eligibility to
  `config/vault_render_optimization-update-notice-state.json` using a sibling
  temporary file, atomic replacement where supported, and safe replacement
  fallback.
- Corrupt or unwritable state is nonfatal and starts a fresh schedule or skips
  the failed write.

## Configuration and commands

The new client configuration section is:

```toml
[updates]
check_for_updates = true
update_types = "CRITICAL"
```

- `updates.check_for_updates` defaults on. Turning it off cancels the active
  request and hides VRO menu/chat notices; turning it on starts a fresh request
  immediately.
- `updates.update_types` accepts `CRITICAL` or `ALL` and defaults to
  `CRITICAL`. Missing or invalid values fail closed to critical-only.
- The selected filter applies to both menu and chat. Changing it reuses the
  fetched result without issuing another request.
- `/vro updates` and `/vro updates status` report both settings.
- `/vro updates on|off` saves and applies the master switch immediately.
- `/vro updates critical|all` saves and applies the severity filter
  immediately.
- Commands remain client-side and require no server permission.

## Forge and release integration

- Added VRO's `updateJSONURL` and CurseForge `displayURL` to `mods.toml`.
- Added shared notifier coordination properties with the short name `VRO`.
- Added the repository-root Forge update manifest for Minecraft 1.18.2.
- Added the notifier source and tests under VRO's own package; no shared
  runtime mod or bundled notifier jar is required.
- Added the Forge Update Notifier MIT license and exact source provenance to
  the repository and runnable jar.

## Automated verification

- All 31 notifier tests pass, covering stable/prerelease ordering, critical
  and normal parsing, filter defaults, the real VRO manifest, malformed and
  missing JSON, non-200 HTTP responses, timeouts, abrupt closure, oversized
  responses, corrupt and unwritable state, five/ten-launch cadence,
  once-per-JVM claims, delayed persistence, and reminder delivery.
- The complete VRO source compiles against VaultCrafters Bootstrap, Asgard-SMP,
  Wolds 0.32.2, Wolds 0.33.0, and Vault Hunters Third Edition profiles.
- The universal release jar is built against the Third Edition baseline with
  the notifier classes, Forge metadata, AGPL license, third-party notices, and
  both required MIT license files embedded.
