# The Vault Render Optimization 0.3.2 - Expanded Release Candidate

Release date: August 3, 2026

VRO 0.3.2 promotes the post-0.3.0 optimization work into the public release
candidate. It retains the original Vault render caches, client collision fast
paths, renderer shortcuts, cleanup, crash guards, key compatibility, and
Compare Mode while adding memory compaction, configurable terrain distance,
optional dynamic lighting, and two rendering/lifecycle corrections.

`0.3.1` was an internal test candidate and was not published.

## Download

Install the runnable artifact:

```text
vault_render_optimization.0.3.2.jar
```

Stop Minecraft and keep only one active VRO JAR. No server installation, world
migration, or cache deletion is required.

## New since 0.3.0

### Lower retained model and block-state memory

- Compact immutable lists replace oversized simple baked-model face lists.
- Models with no culled faces share one empty direction map.
- Identical block-state `faceSturdy` boolean arrays share canonical instances.
- These are the two later FerriteCore reductions absent from the installed
  FerriteCore 4.2.2 baseline; VRO leaves FerriteCore's existing caches intact.

### Configurable terrain-section distance

- Vertical terrain culling is enabled by default at 12 sections above and below
  the camera.
- Circular horizontal culling is independently configurable and disabled by
  default.
- Vanilla and Embeddium/Rubidium render paths are supported.
- Culling affects terrain drawing only. It does not unload chunks or alter
  generation, simulation, server distance, or Distant Horizons storage.
- VRO yields this entire feature to Better Fps - Render Distance when installed.

### Optional spatial dynamic lights

- Held, equipped, and dropped luminous items can light nearby terrain.
- Burning entities, TNT, selected luminous entities/projectiles, item frames,
  and resource-defined block entities are supported.
- Sources use 16-block spatial cells, independent update schedules, and one
  deduplicated set of section rebuilds per tick.
- Item and block-entity definitions can be supplied by resource packs.
- The engine is disabled by default, pauses with Oculus shaders by default, and
  yields completely to Dynamic Lights Reforged when installed.

### Rendering and shutdown fixes

- Vault elixir-orb number text now uses an isolated buffer and restores normal
  particle state, preventing later particles from rendering black.
- Powah's exact-world unload cleanup now uses a narrow class-access bridge,
  preserving long-session cleanup without an `IllegalAccessError` on exit.

## Commands and defaults

| Command | Purpose |
| --- | --- |
| `/vro compare on\|off` | Switches configured performance paths for comparison |
| `/vro culling` | Reports terrain-culling state and distances |
| `/vro culling vertical on\|off\|<1-64>` | Controls vertical terrain distance |
| `/vro culling horizontal on\|off\|<1-64>` | Controls optional horizontal terrain distance |
| `/vro lights` | Reports dynamic-light configuration and live counters |
| `/vro lights on\|off` | Controls the dynamic-light master switch |
| `/vro lights entities on\|off` | Controls entity and item sources |
| `/vro lights block_entities on\|off` | Controls resource-defined block entities |
| `/vro lights shaders on\|off` | Controls use while Oculus shaders are active |
| `/vro lights interval <1-20>` | Controls each source's update interval |

See [Configuration](https://github.com/HoYin1600p/The-Vault-Render-Optimization/blob/v0.3.2/docs/CONFIGURATION.md)
and [Dynamic lights](https://github.com/HoYin1600p/The-Vault-Render-Optimization/blob/v0.3.2/docs/DYNAMIC_LIGHTS.md)
for complete behavior and defaults.

| Environment | Client |

| Custom compatibility target | Vault `3.21.62` |

VRO is client-only. Optional integrations activate only when their target mod
is present, and generic optimizations remain available without Vault Hunters.

## Validation and limits

- The source compiles against all four supported Vault pack families.
- The corrected `0.3.2` JAR loaded and exited cleanly in the Third Edition CMA
  test client without the previous Powah unload exception.
- The published 40-trial performance figures describe the original 0.3.0 core
  optimization campaign. They are not presented as measurements of the new
  optional dynamic-light or terrain-culling settings.
- Dynamic lighting remains off by default. Horizontal culling remains off by
  default. Performance and visual results still depend on the scene and stack.
